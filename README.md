## English Abstract

*Suika-Ball (Bilibili Toy Edition)* is a portrait-mode HTML5 merging game published on the Bilibili Toy platform. Players drop balls onto the field; two balls of the same level merge into the next level, from the smallest "Berry" to the largest "Sunflower" (15 tiers). The build is a single self-contained `index.html` (Canvas 2D, vanilla JS, no framework and no build step), relying only on the Bilibili Toy SDK for account data, cloud storage syncing and leaderboards.

## 一、玩法规则

- **落球与合成**：点击／触摸画面决定落点，小球沿固定落球线落下；同种同级的两颗球相碰即合成高一级的球。
- **15 级球体**：莓莓 → 柠檬 → 薄荷 → 天空 → 葡萄 → 桃桃 → 棉花 → 星星 → 彩虹 → 月亮 → 雪花 → 樱花 → 极光 → 玫瑰 → 向日葵。
- **失败判定**：球体越过基准线后**连续满 2 秒**（`CONFIG.dangerDelay`）即判负（**脉冲盾存续期间不判负**）；越过 0.5 秒开始预警提示。
- **连击**：1 秒内连续合成计入连击（`CONFIG.comboWindow`）。
- **开局球种**：仅前 3 种球（`CONFIG.initialBallKinds`），随分数提高逐步出现更高级球。

### 物理参数（`CONFIG`）

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `gravity` | 1450 | 重力加速度 |
| `restitution` | 0.29 | 球球碰撞弹性 |
| `wallRestitution` | 0.22 | 与容器壁碰撞弹性 |
| `friction` | 0.994 | 每步速度衰减 |
| `launchCooldown` | 0.42 s | 落球冷却 |
| `dangerDelay` | 2 s | 越线判负阈值 |
| `fixedStep` | 1/120 s | 物理固定步长 |

### 自定义能力（球球定制 / 背景定制）

- 球球底色、边框开关、圆形图标（上传图片并裁剪）、球体名称，均可逐级修改，支持「恢复默认」。
- 背景支持图片背景（含缩放与裁剪偏移）与纯色背景；容器颜色、基准虚线颜色可单独调整。
- 方案支持导出／导入（JSON，`format: suika-ball-scheme`），可重命名、复制、删除。
- 内置官方方案对玩家只读，不会被本机自定义覆盖。

## 三、技能系统

| 技能 | 类型 | 规格 |
| --- | --- | --- |
| 金手指 | 主动，手动触发 | 每局 3 次（`fingerMax`，关注作者升级后 5 次）；持续 3.6 s（`fingerDuration`，升级后 5 s）；吸附半径 28、吸附力 4000、作用范围 200（漩涡吸附）。界面显示剩余次数 `x/y`，用尽后置灰 |
| 脉冲盾 | 被动，自动触发 | 每局 5 次（`pulseMax`，关注作者升级后 **8 次**）；每次发射 **3 波**（`pulseWaves`，升级后 **5 波**）；波间隔 0.30 s（`pulseGap`）；波速 560；**基准线以上的球在盾触发的一瞬间检测并清除一次**（之后不再清除；清除为一次性全清）；**护盾存续期间不判负**（危险累计归零，直到最后一个波消失，时长 = 最后一波释放时刻 + 单波存活时长，随波数变化，之后恢复 2 s 判负）；**吸合中的两球半径逐渐缩小至 60 %**（`pulseShrinkTo`，绘制与碰撞同用该半径，贴到一起即合成），若因阻挡拉不动则超时（`pulsePullTimeout` = 0.9 s）放弃并**恢复原尺寸**（`pulseGrowSpeed`）；**同级吸附合成**＝触发瞬间按「同级两两成对、离场源近者优先」在整个场地强制配对，**每波带走一对**，波一释放立即拉合（**不做「波是否扫到」的位置判定**），故全场 3／5 对同级球会被强制靠近并合成；吸合为直接赋速度（520）并清零合成冷却 |

两个技能为二选一装备：点击展品即装备，再次点击取消。

## 四、排行榜与账号体系

游戏采用「B 站账号即游戏账号」的零后端方案：账号身份、云存储、排行榜全部由 Toy 平台提供，不设自建注册与登录界面。

### 榜单数据源

| 榜单 | 平台 board | 说明 |
| --- | --- | --- |
| 全球战区 | board 1 | 直接写入原始分数 |
| 南林战区 | board 2 | 编码值 = 真实分数 × 64 + 学院序号；低 6 位藏学院号，前端反解后本地聚合出各战队总分 |
| 战队作废板 | board 3 | 平台提交「只增不减」，换战队后旧记录无法修改，故把旧编码值广播至此板，聚合时全端剔除 |

- 平台单榜最多返回 **100 条**（服务端硬上限，非客户端限制）；榜外成绩显示为「暂未上榜」。
- 个人榜只保存同一战区 + 同一学院下的最高分，旧的多局记录在打开排行榜或下次启动时自动压缩。
- 未登录状态可正常游玩，成绩与方案仅保存在本机；登录后经云存储同步。

### 云同步

- 云存储键：`synth-ball-profile-v1`（单键存全量档案），冲突策略为「后写优先」，以本机时间戳比较。
- 账号面板提供云同步状态显示与「重新同步」入口。

### 本机存储键

| 键 | 用途 |
| --- | --- |
| `suika-ball-schemes-v1` | 方案列表与当前选中方案 |
| `suika-ball-customizations-v1` | 旧版单方案自定义（兼容读取） |
| `synth-ball-leaderboard-v1` | 本机排行榜缓存 |
| `synth-ball-midautumn-promo-v1` | 中秋上新弹窗「已提示」标记（不进云同步） |

## 五、技术实现要点

- **单文件交付**：全部 HTML／CSS／JavaScript 内联在 `index.html` 中，三套官方方案的图标以 base64 内嵌，因此发布包可直接以文件形式提交平台。
- **渲染**：Canvas 2D，画布按设备像素比（上限 2）放大后用 `setTransform` 统一到 CSS 像素坐标；游戏世界宽度按容器宽自适应（`min(屏宽-50, 390)`），窗口尺寸变化时按比例重排场上球体。
- **物理**：固定步长 1/120 秒的累加器循环，保证不同帧率下手感一致。
- **球体绘制**：径向渐变球体 ＋ 双层白色描边 ＋ 高光椭圆 ＋ 柔光阴影，中心叠加符号／自定义图标；`radiusFor(level) = 19 + level × 6`。
- **音效**：WebAudio 振荡器实时合成（频率滑音 ＋ 增益包络），无外部音频文件；总音量系数 `SFX_SCALE = 9`。
- **键盘**：`Esc` 逐层关闭当前弹窗；输入框内 `Esc` 关闭、回车确认。
- **已知限制**：平台榜单上限 100 条；换战队后旧战队条目无法删改，需依赖 board 3 作废机制。

## 七、本地运行与调试

- **直接运行**：双击 `index.html` 即可在浏览器中游玩（`file://` 协议下功能完整，云同步与排行榜在未登录／离线时自动降级为本机数据）。
- **推荐环境**：Chrome／Edge 等 Chromium 内核浏览器；竖屏（手机模拟器或窄窗口）体验与平台一致。
- **调试开关**：源码内含本机调试后门，供开发期快速验证高等级球：

  ```js
  const DEV_BACKDOOR=true;        // 发布前必须改为 false 或整块删除
  const BACKDOOR_DROP_Y=200;      // 生成时球心的绝对 y（画布坐标；落球线 y = max(88, 画面高 × 0.145)）
  ```

  行为：游戏进行中按 `Ctrl+1` ~ `Ctrl+5`（或小键盘 `1` ~ `5`），立即在落球线下方生成一颗 L10 ~ L14 的球，不消耗手上球、不进入冷却。
  ⚠️ **该快捷键属于作弊入口，发布包必须关闭**：B 站网页版可接键盘，若随包上线将直接破坏排行榜成绩的公平性。

## 八、发布流程（B 站 Toy）

```bash
# 1. 查看当前状态（确认没有审核中的版本）
toy mylist --json

# 2. 预检（本地文件、语法、资源引用）
toy_doctor

# 3. 提交（覆盖上一次提交并重新走审核；显式带上与创建时一致的字段）
toy update 36651732817920 toy-dist --yes \
  --title "合成球球（南林特别版）" --category GAME \
  --poster 封面-poster.png --icon 图标-icon.png \
  --visibility public

# 4. 回读线上状态
toy mylist --json
```

要点：

- **审核中不允许再次提交**：若上一次提交仍为 `auditing`，`update` 会报 `307013「同 toy 已有审核中的版本」`。提交前先查状态，避免白改一轮。
- 提交成功后条目状态为 `auditing`；此时 `url` / `icon_url` / `poster_url` 为 `null` 属正常现象，**过审（`published`）后才会下发**。
- 可见性必须显式写入 `public`，不带 `--visibility` 时不要依赖平台默认值。
- 过审后建议复核线上页面与实际改动是否一致。

### 合规红线

- **不得将「是否关注作者」设计为解锁条件或奖励门槛**：诱导关注为平台社区规则明确限制的行为，作品可能被驳回或下架。
- 关注状态仅可用于状态显示、回馈彩蛋等非门槛用途。
- 发布包内不得保留任何作弊入口（含上文调试后门）。
